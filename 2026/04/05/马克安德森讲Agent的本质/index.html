马克安德森讲Agent的本质

Created2026-04-05|Updated2026-07-06
|Post Views:

podcast 跨国串门计划 483

马克 安德森总是这么有洞见，这次对谈他讲了Agent的本质。听完记录一下：

  1. 在软件世界里，从1973年到Linux诞生一直有一种非常重要的东西，现在也依然重要，就是所谓的unix思维。这个架构是这样的，我们有一个提示符，一个shell，然后所有的功能都以离散模块的形式存在，你可以把这些模块串联起来。没错，所以这就像是操作系统本身变成了一种编程语言，这导致了shell变成了核心。接着，人们开始把UNIX工具串联在一起，随后出现了像Perl这样可以轻松实现这种操作的脚本语言，后来shell变得越来越高级。它是在后台运行，普通人不需要了解它。但如果你做系统架构或应用开发，你肯定对它了如指掌。从那以后它就一直存在于后台。你的Mac其实还有一个UNIX shell, 你的iPhone深处也藏着一个UNIX shell, 所以他们一直都在，Windows的shell算是一个奇怪的衍生品，但你看整个互联网都跑在UNIX上，智能手机、iOS和安卓其实也都是UNIX的衍生品。
  2. 我常说伟大的突破在事后看来都是显而易见的，对吧？这是最棒的一种突破，但在当时并不明显，否则别人早就做了。所以这确实是一个真正的概念性飞跃。但当你回头看时，你会觉得，当然应该这样。对我来说，这种突破总是最棒的。其实语言模型本身也是这样。大家会说，预测下一个token吧。当然了，除了这个目标还能有什么呢？没错，但在有人真正做出来之前，这并不显而易见。所以这种概念上的突破是真实、深刻、强大且非常重要的。我认为PI和openclaw本质上是将语言模型思维与UNIX、shell提示符思维结合在了一起
  3. 那什么是智能体Agent呢？几十年来很多聪明人一直想搞清楚智能体到底是什么，他们设计了各种架构来构建智能体。结果现在我们发现智能体其实是这样的，它底层是一个语言模型，上面是一个bash shell, 也就是一个unix shell, 然后这个智能体可以访问这个shell，最好是在沙盒环境里。所以它是由模型、shell和文件系统组成的，状态存储在文件里，文件采用markdown格式，然后还有UNIX里所谓的cron任务，也就是一个循环，一个心跳，这个东西会不断唤醒。所以它基本上就是大语言模型 + shell + 文件系统 + markdown + cron机制。事实证明，这就是智能体。除了模型之外，这里的每一个部分都是我们已经完全熟悉和理解的。
  4. 事实上，UNIX shell的潜在力量是惊人的，shell里有海量 UNIX命令和命令行接口，可以连接各种事物。首先，如果你用的是Mac或手机，电脑本身就跑在shell上，所有功能在命令行层面都可用。把其他功能暴露为命令行接口非常容易，所以我们不需要像MCP这种花哨的协议，只需要一个命令行接口，这是它的架构。你的智能体是存储在文件系统里的一堆文件。
  5. 当我理解了这一点后，最让我感到震撼的是，这意味着你的智能体现在实际上是独立于它所运行的模型的。因为你可以更换底层的LLM，你的智能体性格可能会变，因为模型变了，但存储在文件里的所有状态都会保留。没错，就像是给一艘船换了引擎并重新编译，但它依然是你的智能体，拥有所有的记忆和能力。顺便说一下，你也可以更换shell，把它移到另一个同样支持bash的执行环境里。你还可以更换文件系统，更换框cron框架，也就是那个循环或者智能体框架本身。所以说到底，你的智能体本质上就是那些文件。
  6. 正因为如此，智能体还有几个重要的特性，一是它可以自我迁移，你可以命令你的智能体把自己迁移到不同的运行环境，不同的文件系统，或者换一个语言模型，智能体会为你完成这一切。最后一点简直太神奇了，那就是智能体实际上具有完全的内省能力，它了解自己的文件，并且可以重写自己的文件。在历史上，没有任何被广泛应用的软件系统能像这样完全了解自己是如何运作的，并且能够修改自己。虽然以前有过一些实验性的系统，但从未有过具备这种能力的广泛应用系统。这又引出了另一个让我震惊的能力，你可以告诉智能体为它自己添加新功能，它就能做到。
  7. 人们可能会看着他说，这算什么突破？这些组件以前不都有吗？但关键在于通过使用已知的组件，获得埋藏在底层的全部能力。例如，电脑操作突然变得易如反掌，他当然能操作电脑，因为有shell的完整权限。然后给浏览器的访问权限，有了电脑和浏览器，它就可以起飞了。这种能力的释放是深远的，我那些深入研究的朋友，已经让他们的openclaw在生活中处理上千件事儿，每天都有新点子，不断提出新挑战。当然，现在还处于早期阶段，这些只是原型，还存在安全问题，有很多细节需要完善。
  8. 当你构建浏览器和互联网时，那时候大多是纯文本文件加一些图像，而现在的每个网站和应用都非常复杂，但浏览器一直在进化以适应这些。那么在早期的浏览器、互联网和协议中，有没有一些设计选择是你现在觉得不适用于这类新型计算的？比如，这东西对新型计算行不通，我们现在该拆掉。第一点要明确，那时候跟现在完全不同，当时没有现在的能力底层，没有语言模型。人类可读性很重要。具体到那时候，不完全是英语语言问题，而是在二进制协议和文本协议之间做设计抉择。1960年代到1990年代，成长起来的老派系统架构师都会说，互联网带宽极度匮乏。所以，你会试图对网络传输的每一比特数据进行机制优化。显然，如果你要设计像HTTP这样的协议，你会希望它是二进制的、高度压缩的二进制协议，以实现最高效率。你会希望它是一个持久的单一连接。你最不想做的就是频繁建立和拆除新连接。你绝对不会想要文本协议。当然，我们的决定是完全反其道而行之。显然，我们只想要文本协议。顺便说一下，HTML本身也是如此。我们希望HTML相对冗长一些，我们希望标签是人类可读的。就像是最初的token上线，其实这是一个有意识的选择，基本上就是说假设未来会有无限的带宽，并为此进行构建。这其实是一场赌博，赌的是如果系统的潜在能力足够强大，而且这种强大对人们来说显而易见，那么它就会创造对带宽的需求，进而促使带宽供应的建设，最终让整件事儿运转起来。
  9. 具体来说，我们希望一切都是人类可读的，因为在工程层面，我们希望人们能直接读取线路上传输的协议，用肉眼就能理解它，而不需要去反汇编或者从二进制转换出来。所以HTTP和所有其他协议一直都是文本协议，HTML也是一样。很多人说浏览器最核心的突破是查看源代码选项，在每个网页上都能查看源码，这意味着你能看到它是怎么运作的，可以自学构建新网页。所以人类可读性在那时是指技术规范，现在意味着英语语言。如果赋予每个使用系统的人深入了解并实际看到它如何运作的选项，蕴含着巨大潜在力量，这对万维网非常奏效，我觉得对人工智能也有效。这是第一点。还有一点，web server的重要理念是把操作系统的底层潜在能力表现出来，同时也把数据库的底层潜在能力表现出来。因为从架构上讲，web服务器本质上是什么？它就是操作系统，管理文件系统，处理所有你想做的事情能力。很多早期网站是数据库前端，所以想要释放底层潜能，无论是Oracle数据库还是Postgre。Web服务器的一大功能是充当互联网连接的桥梁，解锁操作系统和数据库的底层力量。当时人们看着它说，这真的很重要吗？因为数据库一直都有，我们也有数据库用户界面，这不过是另一种数据库界面。行吧，这么说没错。但现在是一个好得多的数据库接口，而且80亿人都会使用。它更易用灵活。于是世界上的数据库数量爆炸式增长。这又回到分层构建的问题上。
  10. 行业里一些最聪明的人在面对新挑战时会觉得，需要构建一种新的应用。所以我第一件事是构建一种新编程语言，第二件事是构建新操作系统，接着构建新芯片，他们想创造一切。但我一直有务实心理，或工程优于科学。我觉得现有系统已有潜在力量，你不想被约束，但想释放并开放这些力量，万维网就是因为这些原因做到了这一点。现在同样的事情正在发生。技术的本质是现有技术的组合
