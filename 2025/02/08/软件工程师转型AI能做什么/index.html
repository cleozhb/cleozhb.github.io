软件工程师转型AI能做什么

Created2025-02-08|Updated2026-07-06
|Post Views:

​ 大模型这件事从2023年刚出来时各种幻觉让人觉得并不可靠，到如今这才2年多的时间已经能回答95%的普通问题，且置信度非常高，更加坚定了我AI这件事一定是here to stay的。行业很新，才3年不到，把大家的起跑线拉到一起了，空间还特别大，是一个未来的技术，我想这时候为什么不去多花点时间去学习呢？最近一直在想怎么转型AI，不仅仅是薪酬上的溢价，更是一种对未来的探索。

从岗位上来说大概分为2类：

  • AI Researcher：至少是PhD为基础，而且现在去读已经有点晚了，现在在做这一代LLM的最核心的模型架构设计的都是几年前一直在搞NLP深度学习的那帮人，这部分需求不多且要求极高，不是普通人能触及的。
  • AI Engineer：包括模型的后训练，微调，workflow设计等等更偏应用层，还是需要先看一下AI stack中包含哪些

AI Stack 要训练一个大模型大概分为几步，分别需要什么知识储备。

将模型从一堆混乱的参数变成一个可以用的产品，比如ChatGPT，大概要经历几步：

  1. Pre-training，将所有互联网上公有的私有的，只要能拿到的都拿到，然后会有一个模型架构，现在最主流的是transformer，attention， encoder-decoder，这种类似的架构，Auto regressive 的output 自己能生成下一个token。简单来说模型做的事就是对所有的语料进行一个压缩，将全人类的知识记到模型参数中。主流架构经过大量语料训练之后的模型只是一个会做文字接龙游戏的模型，他能做的事就是生成下一个token。预训练决定模型上限，这个模型有多智能，绝大多数的能力都在预训练阶段产生了，模型架构确定了，模型效率也确定了。这一部分的工作就是顶级的AI researcher 来定义模型架构，怎样让它的attention变的更好？怎样让它的context window变的更长？怎么样能够让在所有的context里面的内容都能抓取到相关的内容？模型选用dense架构还是MOE这种多专家的架构？所有这种算法层面的创新都在预训练模型架构阶段就已经做好了。占用的资源可能是做post training的十倍到百倍，OpenAI号称训练一次要用多少人多少钱多少卡都是预训练阶段的开销
  2. Post-training 这部分就是让模型和你需要的应用做一个对齐，和人类的偏好进行对齐。比如你想要模型会聊天就要构造聊天数据集微调，模型就会聊天了情商比较高，而不是只生成下一个token那样无限接龙下去。比如一些应用场景，法律、金融、医疗等等进行对齐。也包括强化学习对齐人类的feedback。包括现在的蒸馏模型也是发生在这个阶段，让一个老师模型来教一个学生模型，这种新花样都在Post-training阶段，目标就是让你的产出和人的预期更接近。
  3. model serving 从这里开始就是很多程序员都可以尝试的了，这部分就是把模型有效的在硬件上跑起来，优化一点点，对于整个公司来说会带来巨大的成本节约和效率提升。后训练也有工程的问题在里面，预训练也有工程问题，也就是训练框架层面，基本就是能够并行。一个训练好的模型比如deepseek 包含680B个参数，就是几百G的模型文件，这么大一块数据，模型架构是mix of expert，激活参数10%左右，那要怎么样去高效的去server这个模型，让它能够做推理，让模型非常高效的，以互联网级别的请求比如每天有几千万甚至上亿的用户去访问，怎么把这件事做的高效？LLM很强大，但是通常有点慢。优化方式包括 flash attention（加快attention过程）；speculative decoding；加各种head，各种classifier让输出变的更有效，多个专家怎么样并行到不同的GPU上去，每个GPU跑什么专家，什么时候激活什么时候不激活？总之如果大模型是一个汽车引擎，model server就相当于车的其他框架，这个引擎放在上面还要有交互要有方向盘有刹车有油门。当有输入进来的时候，模型层面只能take一个输入，但是在model server层面，可以把很多输入batch起来，这样一次serving的效率就会高很多。从这个stack来看很多软件工程师能做的事：
    1. 单个机器层面看硬件的使用效率：网络、cpu gpu 利用率、 cache命中率
    2. cuda 开发独特的算子在GPU上更高效的运行，常见的attention在主流框架中都做了这一层的优化，如果有创新的架构可以用cuda实现和GPU更好的结合
    3. 整个distributed system层面，这些参数怎么并行，需求怎么路由用户的input，什么时候batch，怎么样做caching策略，这些就是更上层的东西。
  4. 基本每一家公司都有自己的GPU会做model inference，甚至有创业公司就专门做这件事，帮用户更高效的serving他们的AI traffic，毕竟web application的traffic 和大量数据交互的大量IO为主的network traffic非常不同，很多公司找不到有经验的人。
  5. 现在我们已经有一个训练好的模型，可以高效的在GPU上跑出来，最后一步就是在上面加应用。要有界面，要有workflow，要有其他在上面增加产品的附加价值，Manus ,perplexity, Cursor, windsurf 都是在应用层。一个AI产品并不是简单的写一个prompt，更多的是agent layer, workflow layer 等等，把不同的模块，包括AI和现有系统中非AI的模块能够结合起来，包括RAG等等，包括怎么做储存等等。在模型能力确定的情况下，上层应用做的好对模型的效果还是有非常大的提升。甚至可以简单的同时问三个模型，再把结果汇总起来，能力可能就是比单个要好。这一层的需求是最大的，如何去写AI的workflow？比如说用户来了一个输入，你判断是否需要进行网络搜索，是否需要最新的数据抓取，是否需要清洗，进行增强，和现在的context结合起来，然后用大模型回复一个更好的结果，这个本身就不简单。主要有这么几难点：1. 判断要不要做搜索，这个classify本身就不太好做； 2.拿来了数据之后，怎么样把更相关的数据结合到之前的聊天记录能拿过来，这一步RAG也不太好做；3.怎么让搜索效率更高，比如他反复问这些问题，是不是要做一层cache layer？

在RAG,MCP model的protocal，Agent layer，或者能组织非常强的workflow，包括早期的Langchain基本就是做了这一层的事，用一些workflow让模型的能力看起来增强了，如果能在这一层做的很好也是非常有价值的。

  1. 熟练使用AI工具，知道他们的边界在什么时候能提升效率
  2. 先调prompt，对比不同prompt的效果
  3. 能不能通过vector Database让这个prompt的效果变的更好
  4. 怎么样能让serving的效率变的更高
  5. 理解模型的架构，知道最新的模型在往哪个方向发展，最新的算法是哪些

AI 应用开发工程师路线图

引言

人工智能工程师一词已经演变。如今，人工智能工程师通常意味着：

使用预先训练的AI模型和API构建生产就绪系统的软件工程师。

将OpenAI或Anthropic等公司的模型集成到真实的产品中——聊天机器人、文档处理器、助手和自动化系统。它们在API层的右侧工作。是机器学习工程师和数据科学家正在训练和优化模型。

第一步：学习人工智能工程的基础

  • 建立一个软件工程师的基础，可以编写干净、可维护的Python代码。
  • 正确学习Python编程语言——语法、函数、类和错误处理。
  • 设置您的开发环境（VS Code、PyCharm等）。
  • 使用uv或pip等工具管理依赖关系和虚拟环境。
  • 使用Git和GitHub练习版本控制(clone, branch, commit, merge, PR).
  • 了解Python中的项目结构(modules, imports, init.py)
  • 学习基本的测试、调试和日志记录。
  • 了解如何使用.env文件配置环境变量。
  • 浏览整个OpenAI API文档和Python SDK。学习如何进行身份验证、发送请求、处理响应以及处理结构化输出。

目标：您可以使用干净的代码和结构在本地构建和运行小型Python项目。

第二步：设计真正有效的人工智能系统

在编写代码之前，了解如何思考和设计AI系统。

  • 了解LLM可以构建哪些类型的系统：文档处理、个人助理、内容生成、后端自动化和多代理工作流。
  • 了解有效的人工智能系统尽可能少地使用人工智能——将确定性逻辑与LLM相结合。
  • 研究基于LLM的系统的核心构建块：输入、提示、上下文窗口、输出和反馈循环。
  • 学习关键的软件设计模式：Chain of Responsibility, Facade, Strategy责任链、外观、战略
  • 探索LangChain/LangGraph和PydanticAI等代理框架，以了解编排模式。Explore agent frameworks like LangChain/LangGraph and PydanticAI to understand orchestration patterns.
  • 在您自己的项目中重新实现这些框架的简化版本，以了解它们是如何工作的。Learn to sketch cognitive architectures which are simple block diagrams showing how data flows through your system.
  • 学习绘制认知架构，这些架构是显示数据如何在系统中流动的简单框图。

目标：你可以设计一个端到端的人工智能系统，并清楚地解释每个步骤。

第三步：构建可用于生产的AI后端

将您的本地原型转化为可扩展的后端服务。Turn your local prototypes into scalable backend services.

  • 使用FastAPI和Pydantic构建API进行输入/输出验证。
  • 学习Celery的异步编程，用来保障服务可用性，处理并发请求。
  • 使用Docker将应用程序容器化。
  • 使用PostgreSQL进行数据存储。
  • 使用Alembic管理数据库迁移。
  • 了解事件驱动架构：作业、队列和API如何通信。Understand event-driven architecture: how jobs, queues, and APIs communicate.
  • 学习使用环境变量安全地管理配置和秘钥。
  • 了解MCP服务以及它们如何扩展您的AI应用程序。

目标：您可以在本地或Docker中运行一个小型后端，该后端连接到数据库并公开干净的API路由。Goal: you can run a small backend locally or in Docker that connects to a database and exposes clean API routes.

第四步：使用RAG将AI连接到您的数据

教你的人工智能系统访问和使用外部信息。

  • 了解RAG是什么，以及它为什么能提高LLM的可靠性。
  • 学习如何对文档进行分组并创建嵌入。
  • 使用Chroma、LanceDB、Weaviate或pgvector等向量数据库。
  • 构建一个数据管道来嵌入和存储文档。Build an ingestion pipeline to embed and store documents.
  • 实现相似性搜索和混合搜索。Implement similarity search and hybrid search.
  • 学习提高检索质量的技术：上下文检索、查询扩展、自查询、重新排名。Learn techniques to improve retrieval quality: contextual retrieval, query expansion, self-query, re-ranking.
  • 了解如何评估检索性能并识别故障案例。

目标：您可以将AI系统连接到自定义数据源，并在运行时检索相关上下文。Goal: you can connect your AI system to custom data sources and retrieve relevant context at runtime.

第五步：监控和优化你的人工智能系统

衡量人工智能系统的质量、成本和可靠性。Measure quality, cost, and reliability of your AI systems.

  • 学习可观察性概念和工具——从Langfuse开始学习跟踪和提示管理。
  • 捕获所有LLM调用的跟踪，包括输入、输出、延迟和令牌成本。Capture traces for all LLM calls including inputs, outputs, latencies, and token costs.
  • 创建评估以定期测试您的系统：
    • LLM输出的单元测试 Unit tests for LLM outputs
    • 人类注释数据集 Human-annotated datasets
    • LLM作为法官的比较 LLM-as-a-judge comparisons
  • 学习如何存储和版本化回归测试的数据集。Learn how to store and version datasets for regression testing.
  • 实施安全防护措施（prompt注入、PII过滤、输出验证）。Implement guardrails for safety and security (prompt injection, PII filtering, output validation).
  • 使用Sentry等工具跟踪应用程序错误和异常。

目标：你可以量化性能，及早发现回归，并不断改进你的人工智能应用程序。Goal: you can quantify performance, catch regressions early, and continuously improve your AI applications.

第六步：将人工智能应用程序交付生产

使您的系统稳定可维护

  • 选择一个云提供商（AWS、Azure、GCP、Hetzner或DigitalOcean）并学习基础知识。
  • 设置虚拟机或容器服务。
  • 通过Docker部署应用程序。
  • 配置HTTPS（Caddy）、日志和监控。
  • 安全地管理环境变量和秘钥。
  • 设置健康检查和警报。
  • 部署后跟踪性能、成本和可靠性。
  • 使用GitHub Actions了解CI/CD基础知识。

目标：您可以在类似生产的环境中部署、监控和维护您的AI应用程序。Goal: you can deploy, monitor, and maintain your AI applications in a production-like environment.

Conclusion

如果你一步一步地遵循这个路线图：

  1. 正确学习Python
  2. 了解LLM API, prompt工程，agent应用模式 Master LLM APIs, prompt engineering, agent patterns
  3. 了解系统设计和后端架构 Understand system design and backend architecture
  4. Implement RAG + monitoring
  5. 端到端部署一些实际项目 Deploy a few real projects end-to-end

专注于构建，而不是理论。小批量交付，快速迭代，记录一切，并展示至少三个完整的项目，证明你可以构建和部署真正的人工智能系统。Focus on building, not theorizing. Ship small, iterate fast, document everything, and showcase at least three complete projects that prove you can build and deploy real AI systems.
