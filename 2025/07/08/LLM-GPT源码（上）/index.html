LLM-GPT源码（上）

Created2025-07-08|Updated2026-07-06
|Post Views:

导读

Karpathy这位被马斯克和奥特曼从openai、特斯拉来回挖的大神，在此前的nanoGPT基础上(pytorch实现，没错，也是Karpathy开源的)，在2024年4月开源了一个1249行的纯C实现的gpt2训练+推理项目，项目地址https://github.com/karpathy/llm.c。

对于想彻底搞清楚gpt原理、并深入了解模型的优势、瓶颈的同学，是一个非常合适上手的项目，建议使用电脑对比项目源代码浏览。

  • 阅读基础：了解一定的transformer基本原理，熟悉C语言，熟悉矩阵计算。

  • 看懂gpt源码后，可以收获什么？

    1. 解锁transformer/LLM相关的那些云雾缭绕的关键概念和技术，清晰看透LLM。包括但不限于：模型的超参数是哪些，175B是怎么算出来的，训练一个175B的模型需要多少显存，仅infer一个模型需要多少显存，需要多大的算力Flops，什么是pretrain/post-pretrain/SFT，pretrain/FT分别是怎么构造和组织样本/label的，infer又是如何计算的。

    2. 快速了解使用transformer架构的模型创新，不限于语言模型bert/gpt/gpt2/instruct-gpt/chat-GLM/baichuan/qwen/llama，也包括视觉/多模态的vit/mae/clip/llava等等。比如拿到一份大几十页的qwen-technical-report后，一二十分钟就知道他做了哪些关键迭代，并且在人力/语料/算力资源支持下，可以复现相关模型；比如拿到vit的视觉分类方案，在没有视觉背景的情况下，20分钟可以非常清晰的知道怎么做的图像分类，并可以自己实现/复现相关算法；多模态的clip/llava也是类似，仅仅基于NLP的transformer的基础，可以快速发展为一个前沿多模态技术的研究者/爱好者。

    3. 帮助解决业务问题，包括业务prompt工程/FT训练问题定位，badcase解决方案选型、推理性能优化，以及在边缘设备(netjson/树莓派)上自己做部署、推理的爱好者。

一、gpt2/transformer结构回顾

1、为什么选择2019年的gpt2作为llm.c项目的模型？

用作者Karpathy的说法，因为他是所有LLM的祖师爷，了解了gpt2再去看其他模型如砍瓜切菜。

gpt2 is the grand-daddy of LLMs, the first time the modern stack was put together.

2、gpt2的模型结构回顾

**GPT-1：**在左侧原始的encoder&decoder基础上，通过大胆的做减法，删除encoder仅保留decoder结构，得到了第一版GPT的模型结构。因为没啥可说的，很少有见到介绍gpt-1的模型结构的，原文对模型的描述只有以下两句：

n our experiments, we use a multi-layer *Transformer decoder *[34] for the language model, which is a variant of the transformer [62]. This model applies a multi-headed self-attention operation over the input context tokens followed by position-wise feedforward layers to produce an output distribution over target tokens:

$h_0 = U*W_e + W_p$

$h_l = transformer_block(h_{l-1}) $ ∀i ∈ [1, n]

$P(u) = softmax(h_n * W_e^T)$

where U = (u−k, . . . , u−1) is the context vector of tokens, n is the number of layers, [We] is the token embedding matrix, and [Wp] is the position embedding matrix.

**GPT-2：**在GPT-1的基础上，改进了layernorm操作，从post-norm升级为pre-norm，也就是在重要操作前，提前做一次layernorm，然后在操作后做add residual。一样也是没啥可说的，因此很少有介绍gpt-2模型结构的。原文对模型描述如下：

We use a Transformer (Vaswani et al., 2017) based architecture for our LMs. The model largely follows the details of the OpenAI GPT model (Radford et al., 2018) with a few modifications.

Layer normalization (Ba et al., 2016) was moved to the input of each sub-block, similar to a pre-activation residual network (He et al., 2016) and an additional layer normalization was added after the final self-attention block.

A modified initialization which accounts for the accumulation on the residual path with model depth is used. We scale the weights of residual layers at initialization by a factor of 1/ N where N is the number of residual layers.

The vocabulary is expanded to 50,257. We also increase the context size from 512 to 1024 tokens and a larger batch size of 512 is used.

3、gpt训练目标：自回归预估next_token

$L_1(u)=Σ_ilogP(u_i|u_i-_k,…,u_i-_1;θ)$

在正式发车之前，最后做2点说明：

二、模型定义

知道了模型大致结构后，话不多说，开始手把手撸代码，看完代码后，引言中的问题会一一迎刃而解。

项目仅使用c语言标准库，以下是所有的头文件，在cpu运行;与硬件架构无关，方便迁移至多平台。

1、模型超参定义

模型的超参定义，有且仅有下面的5个，可以唯一的决定模型大小，后面会逐步展开计算过程，先简单解释如下

2、模型参数(ParameterTensors)定义

基于上面的5个超参数，首先定义模型（ParameterTensors），这个就是我们训练的模型。

  1. 下面这个ParameterTensors，就是咱们天天说的“大模型”的模型本尊了；

  2. 共包括16个具体参数，模型7B/13B/175B，就是指的下面这16个参数数组的总长度；

  3. 每个参数使用float浮点数组记录，ParameterTensors本身不分配空间，只是定义参数名称；

  4. 在程序开始阶段，需要把这16个参数初始化、分配内存空间，并将物理文件load到内存/显存中；

  5. 训练结束时，将这个参数表中的16个参数(float数组)dump到磁盘，这就是咱们的大模型。

大模型ParameterTensors定义，包括16个float数组参数，16个数组的长度加和就是模型大小，如7B

3、与模型参数ParameterTensors对应，还需要定义一个ActivationTensors

ActivationTensors的定义，包括23个参数;后续的初始化、内存分配逻辑与parameterTensor完全一致

等等，为什么又多了一个结构定义，又来了23个参数，完全搞不清楚一堆一堆的参数之间的关系啊

  • 让我们回顾基础的神经网络结构，在一次如下图所示的【输入 -> 线性变换 -> 激活函数非线性变换 -> 输出】过程中，仅在线性变换中存在待学习的参数W/B，并在Feed Forward过程中顺带产出了input、h、y三层，这三层（就是ActivationTensors）需要记录下来，用于后续的Back Propagation。

  • 在transformer中的LayerNorm、Attention计算中，会产出比基础变换更多的中间变量，用于后续的Back Propagation。ActivationTensors的层数通常大于参数层数，在gpt2中，参数有16层(组)，ActivationTensors有23层(组)，对照下面完全展开的gpt2模型结构，你能找到对应的16层参数、23层的ActivationTensors吗？

4、最后的最后，为了支持训练、推理，在ParameterTensors、ActivationTensors的基础上，进一步增加了一些计算得到的、中间辅助参数，主要是和梯度有关，定义最终的内存数据结构GPT2

  • 4*ParameterTensors：参数与他们的梯度一一对应，因此需要在参数的基础上*2；adam需要记录全局累积的梯度动量表、梯度方差表，再加2*ParameterTensors；加起来是4倍的ParameterTensors参数量；

  • 2*ActivationTensors：activation与自己对应的梯度一一对应，*2；这里有两个问题：1）activation为什么不需要adam的梯度表？2）activation的参数量是多大，比ParameterTensors大还是小，谁起主要作用？

  • 如果只做推理，则4个ParameterTensors可以降为1个，2个ActivationTensors也可以降低为1个，参数量至少可以减少2/3，对显存极大利好；

  • 开始时看不懂可以先混个脸熟，有个大致有个概念，随着后续把每个参数都用起来，他们的作用、影响就会显而易见。

四、小结

通过上文对模型定义和样本构造的源码解读，我们可以知道：

1、175B的参数量是怎么算的？

  • 16个参数总量：（V+maxT+2）*C+ 12*L*C*C + 13*L*C + 2*C

  • 考虑到数量级，简化为：（V+maxT）*C+ 12*L*C*C

    1. 对1B以下的小模型，词表大小V，序列长度maxT贡献了一定比例的参数量，但随着模型增大，这两部分的参数量可以忽略不计；

    2. 对于1B以上的大模型，可以进一步简化为：12L*C*C

  • 可以看到，所谓的大模型，参数量主要消耗在常规的FFN上，占了2/3左右

2、推理、训练需要多少显存？

  • 训练：（4*ParameterTensors + 2*ActivationTensors）*量化精度

  • 推理：（1*ParameterTensors + 1*ActivationTensors）*量化精度

  • 如果按照fp16(2Byte)量化，则主流nvidia显卡可支持的最大模型规模大致如下；显存只是显卡的关键指标约束之一，关于算力和带宽留待下文介绍。

3、pretrain/post-pretrain/SFT：

  • pretrain和post-pretrain的技术原理完全一致，没有任何diff。两个名字主要是从大模型产业链的位置和模型用途来区分的：

    1. pre-train&SFT通常为大模型原厂，为通用AGI大模型训练的基座，不对任何具体业务做训练强化，模型ready后打包、发布出来。

    2. 各个应用方、业务方拿到基座模型，再根据自身业务需求，找到与自己业务最相关的语料，再做一次pre-train，这个train的结果几乎只能用于自己业务。

    3. 当然如果有人愿意把post-pretrain的结果再打包成一个基座模型，发布出去供第三方、下游业务任务使用，那么可以改名叫middle-pretrain，总之就是个名字，原理、技术与pre-train完全一致，就是本文的实现逻辑。

  • SFT同理，技术完全一致。

    1. 模型厂商所做的SFT通常为NLP通用型的高频任务，不针对任何业务场景，比如分类、相关性、摘要、翻译；

    2. 业务方反之为特定目标进行子任务的样本精标，然后做有监督学习、训练，label可以是0/1，也可以继续是自然语言的token
