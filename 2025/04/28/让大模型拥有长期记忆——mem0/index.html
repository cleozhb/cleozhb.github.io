让大模型拥有长期记忆——mem0

Created2025-04-28|Updated2026-07-06
|Post Views:

简介

https://github.com/mem0ai/mem0/tree/ce8a285003a83f3d139a441f3ae5b8f8e5f1b836

https://docs.mem0.ai/introduction

mem0 是一种内存架构，它使 AI Agent 能够长时间保持连贯且语境丰富的对话。与传统方法难以处理固定的上下文窗口不同，mem0 能够智能地从对话中提取、整合和检索有效信息。

  • 两阶段记忆流水线：提取阶段从对话中捕获关键信息，更新阶段智能管理知识库
  • 选择性记忆形成：仅存储关键信息而非整个对话块
  • 智能操作：自动确定是否添加、更新或删除记忆
  • 高效检索：使用向量嵌入快速查找相关记忆
  • 图增强选项：Mem0ᵍ 变体将记忆表示为有向标记图，用于复杂的关系推理

mem0持久的结构性存储，让AI有效记得用户偏好，适应不断变化的环境，并在多个会话之间保持一致的交互。

核心组件

Prompt

默认实现可以参考这个文件：https://github.com/mem0ai/mem0/blob/main/mem0/configs/prompts.py 。默认的prompt可以学习学习，比如如何做few shot，这样可以理解mem0内部做了什么

prompt非常重要!!! 因为在prompt中必须利用大模型的指令遵循能力，强制大模型返回带有facts参数的json对象，否则DeepSeek模型可能无法稳定地输出符合 mem0 严格格式要求的JSON，或者不支持必需的 Function Calling 能力。使用中可以根据场景微调 prompt，通过配置文件进行配置：custom_fact_extraction_prompt 和 custom_update_memory_prompt

  1. MEMORY_ANSWER_PROMPT：指导系统根据检索到的记忆来回答问题，确保响应准确、简洁，并且在未找到相关记忆时也始终保持帮助。
  2. FACT_RETRIEVAL_PROMPT：提取阶段的提示词，用于从对话中提取结构化的事实。它能识别个人偏好、详细信息、计划、活动、健康信息和专业细节，并将其组织成 JSON 列表格式。
  3. DEFAULT_UPDATE_MEMORY_PROMPT：处理更新阶段，展示系统如何通过四种操作管理记忆：
    1. ADD：使用新 ID 创建新的记忆条目。
    2. UPDATE：修改现有记忆，同时保留其 ID。
    3. DELETE：删除被新信息否定或矛盾的记忆。
    4. NONE：当信息已存在时不进行任何更改。
  4. PROCEDURAL_MEMORY_SYSTEM_PROMPT：创建代理与人类交互的综合性摘要，并附带结构化元数据。

get_update_memory_messages()函数将检索到的记忆与新事实相结合，应用更新逻辑以维护一个连贯、无冗余的记忆存储。

配置

mem0 提供了广泛的配置选项，允许您根据需要自定义其行为。这些配置涵盖了向量数据库、语言模型、嵌入模型和图数据库等不同组件。

重点：

  1. 因为mem0默认的LLM是ChatGPT。OpenAI的默认embedding模型是text-embedding-3-small是1536维度。mem0使用向量数据库qdrant创建collection的时候使用的默认embedding_model_dims也是1536维。一开始我只将embedder配置为huggingface的模型sentence-transformers/all-MiniLM-L6-v2 它的维度是384。qdrant中创建的collection维度忘记改了，还是默认的1536维。导致后续在进行add操作的时候因为嵌入模型返回的维度和向量数据库不同，所以失败了写不进去。不管用什么embedding模型和向量数据库，有一个原则就是：保证embedding模型的维度和向量数据库的维度一致
  2. 在配置中custom_fact_extraction_prompt和custom_update_memory_prompt参数非常重要，如果不知道怎么改不要乱改。否则可能会导致大模型不能输出稳定的json格式，导致mem0无法进行function calling，导致报错。默认实现参考FACT_RETRIEVAL_PROMPT和DEFAULT_UPDATE_MEMORY_PROMPT

实现原理

当调用 memory.add()时，会发生以下过程：

该过程遵循以下步骤：整个过程中用到了两次大模型功能：提取事实；对比事实和现有记忆生成具体数据库的操作；

  1. 消息解析
  • 消息被解析成适合处理的格式。
  • 系统消息被过滤掉。
  • 源代码：mem0/memory/main.py
  1. 事实提取
  • 系统使用 LLM 从对话中提取关键事实。
  • 事实被结构化为 JSON 格式。
  • 源代码：mem0/memory/main.py
  1. 记忆管理
  • 新事实与现有记忆进行比较
  • 系统决定是：
    • 添加新记忆
    • 更新现有记忆
    • 删除被否定或矛盾的记忆
    • 不执行任何操作
  • 源代码：mem0/memory/main.py
  1. 存储
  • 记忆被存储在向量数据库中以进行语义搜索。
  • 可选的图存储用于关系信息。
  • 记录所有变更记录。
